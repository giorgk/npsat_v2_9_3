## Project Overview

NPSAT v2.9.3 is a 3D groundwater flow simulation and particle transport framework built on the [deal.II](https://www.dealii.org/) finite element library (v9.3.0). It is used for simulating nonlinear transient groundwater flow and contamination transport in hydrogeological systems, developed at UC Davis.

The project produces **two executables**:
- `npsat_v2` — groundwater flow simulation (finite element solver)
- `npsat_trace` — particle transport/streamline tracing through computed velocity fields

## Build

Requires deal.II 9.3.0, MPI, Trilinos/Aztec (via deal.II), and Boost.

```bash
mkdir build && cd build
cmake -DDEAL_II_DIR=/path/to/deal.II ..
make npsat_v2       # Build flow solver
make npsat_trace    # Build particle tracer
make                # Build both
```

The `debug2/` directory in the repo contains an existing build tree generated by CLion.

There are no automated tests or linting configuration in this project.

## Architecture

### Two Independent Pipelines

**Flow simulation** (`npsat_flow/`, entry: `npsat_v2.cpp`):
1. Parse config → generate/refine mesh → assemble FEM system → solve nonlinear flow → write outputs + trace data

**Particle transport** (`npsat_trace/`, entry: `npsat_trace.cpp`):
1. Load flow outputs (velocities, mesh) → read particle seeds → integrate particle paths → write streamlines/breakthrough curves

These run sequentially: flow must complete first to produce velocity fields that trace consumes.

### Flow Module (`npsat_flow/`)

Uses a **hybrid mixed finite element formulation** (RT0 for flux + DG for pressure + trace elements for BCs), assembled in `main_class_impl/`. The nonlinear solver is a damped Picard iteration with Anderson acceleration.

Key files:
- `flow_input.h` — INI-style config parsing via Boost.Program_Options
- `mesh_gen.h` — structured (BOX) and file-based mesh generation with adaptive refinement
- `mnwells.h` — multi-node well handling with head-dependent conductance
- `streams.h` — stream/surface water interactions
- `mpi_helpers.h` — MPI communication utilities
- `BC/` — boundary condition types: Dirichlet, Neumann, General Head (GHB)
- `interpolation/` — spatial interpolation of properties (constant, gridded, scattered)
- `main_class_impl/npsat_flow_assemble.impl.h` — FEM matrix assembly
- `main_class_impl/npsat_flow_solve.impl.h` — linear + nonlinear solver
- `main_class_impl/npsat_flow_checkpoint.impl.h` — checkpoint save/load
- `main_class_impl/npsat_flow_write_trace.impl.h` — writes face velocities and water table for trace module

### Trace Module (`npsat_trace/`)

Two transport methods (selected via `TransportMethod` config key):
- `"point"` — legacy per-particle streamline integration
- `"trajectory_atlas"` — precomputes trajectory bundles per element (`traj_atlas.h`, 923 lines)

Four velocity interpolation schemes (selected via `VelocityInterpolation`):
- `"split_rt0"` — exact RT0 element-based interpolation; sub-divides elements into tetrahedra
- `"coarse_rt"` — ordinary six-face RT0 interpolation using the coarse-dominated velocity export
- `"idw"` — inverse-distance weighted from scattered velocity samples
- `"cell_idw"` — cell-centered IDW

With `Save_trace_data` enabled, flow output keeps the legacy fine-dominated
velocity export by default. `Save_fine_velocities` and
`Save_coarse_velocities` select either or both velocity datasets.

Key files:
- `cached_velocity.h` — cell-based velocity caching with lazy evaluation (1816 lines)
- `traj_atlas.h` — trajectory atlas for efficient bulk tracing
- `rt0_face_map.h` — maps RT0 face-normal fluxes to local element face ordering
- `trace_help_func.h` — particle seeding, well capture, MPI particle exchange
- `main_class_impl/npsat_trace_point.impl.h` — per-point streamline integration
- `main_class_impl/npsat_trace_atlas.impl.h` — atlas-based trajectory tracking

### Nonlinearity (Unconfined Flow)

The solver handles unconfined (water table) conditions via:
- **Relative conductivity** `r(h)`: scales hydraulic conductivity by cell saturation fraction
- **Effective storage** `S_eff(h)`: smooth sigmoid blending of specific storage (Ss) and specific yield (Sy) using a configurable transition zone (epsilon ≈ 0.05 m)
- **Recharge routing**: head-dependent assignment moves recharge downward until saturation threshold met

See `NONLINEARITY_AND_CONVERGENCE_REVIEW.md` for detailed derivations and convergence analysis.

### Configuration System

Both executables read INI-style files via Boost.Program_Options. Key sections:

**Flow** (`flow_input.h`): `[Paths]`, `[Geometry]`, `[Discretization]`, `[Refinement]`, `[BC]`, `[Properties]`, `[Sources]`, `[IC]`, `[Simulation]`, `[Spinup]`, `[Solver]`, `[NonlinearControls]`

**Trace** (`trace_input.h`): `[Data]`, `[Simulation]`, `[IDW]`

### Implementation Pattern

Most class methods are split into separate `.impl.h` files under `main_class_impl/` and `#include`d into the main class header. This keeps large classes navigable. All headers are included directly into the two `.cpp` translation units — no separate `.cpp` source files exist in the modules.

### Output Formats

- **Flow**: VTK/VTU files (ParaView-compatible), CSV water budgets, binary velocity/water-table files for trace, binary cell-well connectivity maps
- **Trace**: VTK streamlines (ASCII or binary), breakthrough curve CSVs, particle history files

### MPI Parallelism

Flow uses deal.II's distributed triangulation and Trilinos linear algebra. Trace distributes particles across MPI ranks with exchange via `trace_help_func.h`. Use `ConditionalOStream` (rank-0 only) for diagnostics — this pattern is used throughout.

### Embedded Third-Party Library

`npsat_flow/nanoflann.hpp` — header-only KD-tree library used for spatial nearest-neighbor queries (well/stream proximity searches).
